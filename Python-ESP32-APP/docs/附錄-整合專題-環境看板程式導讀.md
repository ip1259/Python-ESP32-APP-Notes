# 延伸選讀：環境看板整合程式導讀

> 延伸選讀｜對應主線：[整合專題：完成環境看板](08-整合專題.md)

這一頁帶你讀懂第八節已成功運作的整合程式：一筆溫溼度資料如何從 ESP32 流到 CSV、圖表與 Gradio，又如何把 LED 命令送回 ESP32。這不是另一套操作步驟；主線程式能正常運作後再閱讀即可。

## 讀完後你會知道

- ESP32 與 Python 在環境看板中各自負責什麼。
- 一次「讀取並記錄資料」如何同時更新資料檔、圖表與網頁。
- LED 命令、感測資料與錯誤訊息如何共用同一條 UART。
- 出問題時，應先查看韌體、UART、CSV／圖表或 Gradio 的哪一段。

## 先知道這件事

主線第八節的核心成果已經包含一支 ESP32 韌體 `integrated_lcd_uart.ino` 與一支 Python 程式 `integrated_dashboard.py`。同一個 COM 埠只由這支 Python 程式開啟；不要同時啟動其他 UART Python 程式或 Arduino 序列監控。

資料和命令的方向如下：

```text
DHT11 → ESP32 韌體 → 一行 JSON → Python → CSV → Pandas／Matplotlib → Gradio
                 ↑                                      │
                 └──────── LED／read_now 命令 ───────────┘
```

LCD 由 ESP32 直接更新；Python 不必透過 UART 逐字控制 LCD。這種分工讓硬體讀值和電腦端的資料記錄各自有清楚的位置。

## 先看責任分工

| 位置 | 負責的事 | 不負責的事 |
| --- | --- | --- |
| ESP32 韌體 | 讀取 DHT11、更新 LCD、接收命令、回覆 JSON、控制板載 LED | 寫入電腦 CSV、產生 PNG 圖、建立網頁 |
| Python 程式 | 開啟唯一的 COM 埠、要求資料、寫入 CSV、畫圖、更新 Gradio | 直接讀 DHT11、直接控制 LCD I2C 腳位 |
| Gradio | 顯示 Python 回傳的文字、表格、圖與狀態；把按鈕事件交給 Python 函式 | 自己開啟第二個 COM 埠或直接和 ESP32 對話 |

這張表也是故障分流的起點。例如 LCD 正常而 CSV 沒新增資料，先從 UART 與 Python 端檢查；不是先更改 LCD 接線。

## ESP32：完整韌體導讀

以下是主線 `integrated_lcd_uart.ino` 的完整導讀快照。只加入 `// 【編號】` 註解，程式行為與主線相同。

整數編號說明一個函式或程式區塊的責任；小數編號說明該區塊中的關鍵步驟。例如【10】是「讀取並送出感測資料」，【10.2】則是「讀值失敗時的判斷」。

執行位置：Arduino IDE／ESP32  
來源檔案：`integrated_lcd_uart.ino`

```cpp linenums="1"
// 【1】匯入 I2C、LCD 與 DHT11 所需的函式庫
#include <Wire.h>
#include <LiquidCrystal_I2C.h>
#include <DHT.h>

// 【2】集中定義硬體腳位、LCD 位址與定時讀值間隔
const int DHT_PIN = 4;
const int LED_PIN = 2;
const int SDA_PIN = 21;
const int SCL_PIN = 22;
const byte LCD_ADDRESS = 0x27;
const unsigned long SENSOR_INTERVAL_MS = 2000;

#define DHT_TYPE DHT11

// 【3】建立 LCD 與 DHT11 物件，供後面的函式共用
LiquidCrystal_I2C lcd(LCD_ADDRESS, 16, 2);
DHT dht(DHT_PIN, DHT_TYPE);

// 【4】保留上次讀值時間，並累積尚未完成的一行命令
unsigned long last_sensor_time = 0;
String command_buffer = "";

// 【5】先宣告函式，讓命令處理函式可在定義前呼叫它
void readAndSendSensor(const char *source);

// 【6】覆寫 LCD 單行前先清空舊文字，避免殘留較長的內容
void printLine(int row, String text) {
  // 【6.1】先移到目標列的開頭
  lcd.setCursor(0, row);
  // 【6.2】用 16 個空白覆蓋可能殘留的舊文字
  lcd.print("                ");
  // 【6.3】回到開頭，只顯示前 16 個字元以符合 LCD 寬度
  lcd.setCursor(0, row);
  lcd.print(text.substring(0, 16));
}

// 【7】LED 命令完成後，以 JSON 回覆目前狀態給 Python
void sendLedStatus(bool is_on) {
  // 【7.1】三元運算子將 bool 轉成 JSON 所需的 true 或 false 文字
  Serial.printf(
    "{\"type\":\"status\",\"led\":%s,\"ok\":true}\n",
    is_on ? "true" : "false"
  );
}

// 【8】依一整行 JSON 命令決定要控制 LED、讀取資料或回覆錯誤
void handleCommand(String command) {
  // 【8.1】移除命令前後可能附帶的空白與換行字元
  command.trim();

  // 【8.2】辨識 LED 開啟命令，更新 GPIO 後回傳相同狀態
  if (command == "{\"cmd\":\"led\",\"value\":true}") {
    digitalWrite(LED_PIN, HIGH);
    sendLedStatus(true);

  // 【8.3】辨識 LED 關閉命令，處理方式和開啟時相同
  } else if (command == "{\"cmd\":\"led\",\"value\":false}") {
    digitalWrite(LED_PIN, LOW);
    sendLedStatus(false);

  // 【8.4】要求立即讀值時，將回覆標記為 request
  } else if (command == "{\"cmd\":\"read_now\"}") {
    readAndSendSensor("request");

  // 【8.5】非空白但不認識的命令以 error JSON 回覆
  } else if (command.length() > 0) {
    Serial.println("{\"type\":\"error\",\"message\":\"unknown command\"}");
  }
}

// 【9】逐字接收資料；讀到換行才交出一筆完整命令
void readSerialCommands() {
  // 【9.1】只要接收緩衝區還有字元，就持續逐字讀取
  while (Serial.available()) {
    char received = static_cast<char>(Serial.read());

    // 【9.2】換行代表一筆命令結束，交給命令處理函式
    if (received == '\n') {
      handleCommand(command_buffer);
      // 【9.3】處理完後清空，準備累積下一筆命令
      command_buffer = "";

    // 【9.4】忽略 Windows 換行中的 \r，避免它混進 JSON
    } else if (received != '\r') {
      // 【9.5】其他字元仍屬於同一筆命令，繼續累積
      command_buffer += received;
    }
  }
}

// 【10】讀取 DHT11；成功時更新 LCD 與送出 JSON，失敗時也送出 error JSON
void readAndSendSensor(const char *source) {
  // 【10.1】讀取 DHT11 的兩個欄位
  float humidity = dht.readHumidity();
  float temperature = dht.readTemperature();

  // 【10.2】任一欄位不是數字時，不能當成有效感測資料
  if (isnan(humidity) || isnan(temperature)) {
    // 【10.3】硬體端先顯示錯誤，方便不看電腦時排查
    printLine(0, "DHT read failed");
    printLine(1, "Check wiring");

    // 【10.4】電腦端收到同樣來源的 error JSON
    Serial.printf(
      "{\"type\":\"error\",\"source\":\"%s\",\"message\":\"dht read failed\"}\n",
      source
    );
    return;  // 【10.5】失敗時停止，不再往下顯示或傳送 sensor JSON
  }

  // 【10.6】成功時先更新 LCD，再送出同一筆資料的 JSON
  printLine(0, "T:" + String(temperature, 1) + " C");
  printLine(1, "H:" + String(humidity, 1) + " %");

  Serial.printf(
    "{\"type\":\"sensor\",\"source\":\"%s\",\"temp\":%.1f,\"humidity\":%.1f}\n",
    source,
    temperature,
    humidity
  );
}

// 【11】開機時只做一次的序列埠、I2C、LCD、DHT11 與 LED 初始化
void setup() {
  // 【11.1】先開啟與 Python 相同鮑率的 UART
  Serial.begin(115200);

  // 【11.2】設定板載 LED 並指定開機預設為關閉
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);


  // 【11.3】使用指定 SDA／SCL 建立 I2C，再初始化 LCD
  Wire.begin(SDA_PIN, SCL_PIN);
  lcd.init();
  lcd.backlight();
  printLine(0, "AIoT dashboard");
  printLine(1, "Starting...");

  dht.begin();  // 【11.4】最後啟動 DHT11 函式庫
}

// 【12】持續先處理命令，再依時間定時傳送 periodic 感測資料
void loop() {
  // 【12.1】每一輪都先處理命令，避免命令被兩秒週期阻塞
  readSerialCommands();

  // 【12.2】只有經過設定間隔才送出定時感測資料
  if (millis() - last_sensor_time >= SENSOR_INTERVAL_MS) {
    // 【12.3】更新計時基準，並標記資料來源為 periodic
    last_sensor_time = millis();
    readAndSendSensor("periodic");
  }
}
```

讀取順序是【1】至【5】準備工具與共用資料、【6】至【10】定義實際工作、【11】開機設定、【12】重複執行。最容易忽略的是【9】：沒有它，Python 送來的 JSON 命令不會在換行後被交給【8】處理。`request` 與 `periodic` 的差異請接著閱讀[延伸選讀：UART JSON、緩衝區與請求／回應](附錄-UART-JSON緩衝區與請求回應.md)。

## Python：完整儀表板程式導讀

以下是主線 `integrated_dashboard.py` 的完整導讀快照。只加入 `# 【編號】` 註解，程式行為與主線相同。

執行位置：Python／電腦  
來源檔案：`integrated_dashboard.py`

```python linenums="1"
# 【1】匯入標準函式庫：檔案、JSON、時間與路徑
import csv
import json
import time
from datetime import datetime
from pathlib import Path

# 【2】匯入儀表板、圖表、表格與序列埠套件
import gradio as gr
import matplotlib.pyplot as plt
import pandas as pd
import serial
from matplotlib.figure import Figure

# 【3】集中設定 COM 埠、鮑率與輸出檔案位置
PORT = "COM3"
BAUD_RATE = 115200
CSV_PATH = Path("data/sensor.csv")
CHART_PATH = Path("charts/temperature_humidity.png")
JsonData = dict[str, object]
SensorRow = dict[str, str | float]


# 【4】一個物件集中管理唯一的 COM 埠與所有 UART 工作
class IntegratedDashboard:
    def __init__(self) -> None:
        # 【4.1】開啟指定的序列埠；timeout 讓 readline 最久只等半秒，避免介面永久卡住。
        self.ser: serial.Serial = serial.Serial(PORT, BAUD_RATE, timeout=0.5)

        # 【4.2】ESP32 剛開啟序列埠時可能重新啟動，先等它完成開機。
        time.sleep(2)

        # 【4.3】丟棄開機期間殘留的輸出，後續才從完整的一行 JSON 開始讀取。
        self.ser.reset_input_buffer()

    # 【5】程式結束時釋放 COM 埠，避免下一次開啟被占用
    def close(self) -> None:
        # 【5.1】只有序列埠仍開啟時才關閉，避免重複關閉時出錯。
        if self.ser.is_open:
            # 【5.2】釋放作業系統占用的 COM 埠，程式結束後才能被其他工具使用。
            self.ser.close()

    # 【6】讀一行 UART 文字，只有合法 JSON 才回傳字典
    def read_json(self) -> JsonData | None:
        # 【6.1】讀取一行；ESP32 的 printLine() 已保證每筆 JSON 都以換行結束。
        raw = self.ser.readline().decode("utf-8", errors="replace").strip()

        # 【6.2】逾時或只有空白時，不嘗試解析不存在的資料。
        if not raw:
            return None

        try:
            # 【6.3】將文字 JSON 轉回 Python 字典，供後續用 key 取值。
            return json.loads(raw)
        except json.JSONDecodeError:
            # 【6.4】遇到開機訊息或破損資料時略過，下一輪再讀新的完整資料。
            return None

    # 【7】清掉舊資料、要求 read_now，並只接受 source 是 request 的回覆
    def read_sensor(self) -> tuple[SensorRow | None, str | None]:
        # 【7.1】先清空先前的定時推送，避免把舊測值誤當成這次按鈕要求的結果。
        self.ser.reset_input_buffer()

        # 【7.2】建立與 ESP32 handleCommand() 約定好的命令內容，再以換行表示命令結束。
        message = json.dumps({"cmd": "read_now"}, separators=(",", ":")) + "\n"

        # 【7.3】write 寫入資料；flush 確保緩衝中的命令立即送出。
        self.ser.write(message.encode("utf-8"))
        self.ser.flush()

        # 【7.4】以截止時間限制等待總長度，不因一直收到不相關資料而無限等待。
        deadline = time.monotonic() + 4

        # 【7.5】持續讀取，直到收到本次要求的 sensor 資料，或超過四秒。
        while time.monotonic() < deadline:
            data = self.read_json()

            # 【7.6】只接受 type=sensor 且 source=request；periodic 是背景定時資料，不能當答案。
            if data and data.get("type") == "sensor" and data.get("source") == "request":
                # 【7.7】整理成一列；float 讓 CSV 與圖表取得真正的數值，而非文字。
                return {
                    "timestamp": datetime.now().isoformat(timespec="seconds"),
                    "temp_c": float(data["temp"]),
                    "humidity": float(data["humidity"]),
                }, None

            # 【7.8】ESP32 明確回報本次感測失敗時，立即把原因交給介面顯示。
            if data and data.get("type") == "error" and data.get("source") == "request":
                return None, data.get("message", "ESP32 error")

        # 【7.9】截止時間已到仍無回應，回傳可閱讀的狀態，而不是讓例外中斷介面。
        return None, "4 秒內沒有收到本次讀取的 sensor JSON"

    # 【8】將一列成功的感測資料追加到 CSV，首次建立時寫入表頭
    def append_csv(self, row: SensorRow) -> None:
        # 【8.1】父資料夾不存在時先建立，才能安全寫入 CSV。
        CSV_PATH.parent.mkdir(exist_ok=True)

        # 【8.2】在開檔前判斷檔案是否存在，決定是否需要寫欄位名稱。
        is_new = not CSV_PATH.exists()

        # 【8.3】以附加模式開啟；newline="" 避免 Windows CSV 出現多餘空白列。
        with CSV_PATH.open("a", newline="", encoding="utf-8") as file:
            # 【8.4】DictWriter 依欄位名稱寫入，字典 key 的順序不會影響 CSV 欄位順序。
            writer = csv.DictWriter(file, fieldnames=["timestamp", "temp_c", "humidity"])

            # 【8.5】只有新檔案寫入標題列，既有資料不會被重複加上標題。
            if is_new:
                writer.writeheader()

            # 【8.6】把本次最新資料附加成一列，供圖表和日後分析使用。
            writer.writerow(row)

    # 【9】從 CSV 讀取、清理最近資料，並建立 PNG 與 Figure
    def dataframe_and_chart(self) -> tuple[pd.DataFrame, Figure]:
        # 【9.1】讀入歷史 CSV，接下來會同時提供表格資料與趨勢圖。
        data = pd.read_csv(CSV_PATH)

        # 【9.2】將文字欄位轉成日期與數字；errors="coerce" 會把不合法內容標成缺值。
        data["timestamp"] = pd.to_datetime(data["timestamp"], errors="coerce")
        data["temp_c"] = pd.to_numeric(data["temp_c"], errors="coerce")
        data["humidity"] = pd.to_numeric(data["humidity"], errors="coerce")

        # 【9.3】移除無法使用的列，並只保留最近 20 筆，讓圖表不會隨時間過度擁擠。
        data = data.dropna().tail(20)

        # 【9.4】建立上下兩張共用時間軸的圖；fig 是整張畫布，兩個 ax 是各自的座標區。
        fig, (temp_ax, humidity_ax) = plt.subplots(2, 1, sharex=True, figsize=(8, 5))
        # 【9.5】分別把溫度、濕度畫到對應座標區，marker 讓單筆測值也容易辨認。
        temp_ax.plot(data["timestamp"], data["temp_c"], marker="o", color="tab:red")
        humidity_ax.plot(data["timestamp"], data["humidity"], marker="o", color="tab:blue")

        # 【9.6】補齊單位、時間標籤與格線，否則線條本身不容易解讀。
        temp_ax.set_ylabel("Temperature (°C)")
        humidity_ax.set_ylabel("Humidity (%)")
        humidity_ax.set_xlabel("Time")
        temp_ax.grid(True)
        humidity_ax.grid(True)

        # 【9.7】調整日期格式與留白，建立圖檔資料夾後輸出 PNG。
        fig.autofmt_xdate()
        fig.tight_layout()
        CHART_PATH.parent.mkdir(exist_ok=True)
        fig.savefig(CHART_PATH, dpi=150)

        return data, fig

    # 【10】送出 LED 命令，並等待 ESP32 回覆相同狀態的 status JSON
    def set_led(self, value: bool) -> str:
        # 【10.1】控制前同樣清空舊訊息，避免舊的 status 被誤認為這次控制結果。
        self.ser.reset_input_buffer()

        # 【10.2】把 Python 布林值放進 JSON；json.dumps 會輸出 ESP32 可解析的 true 或 false。
        message = json.dumps({"cmd": "led", "value": value}, separators=(",", ":")) + "\n"

        # 【10.3】送出命令後，在五秒內等 ESP32 回傳確認訊息。
        self.ser.write(message.encode("utf-8"))

        deadline = time.monotonic() + 5
        while time.monotonic() < deadline:
            data = self.read_json()

            # 【10.4】確認回應類型和 LED 狀態都符合預期，才回報控制成功。
            if data and data.get("type") == "status" and data.get("led") == value:
                return "LED 已開啟" if value else "LED 已關閉"

        # 【10.5】沒有等到相符確認時，保留明確訊息讓使用者知道要檢查連線。
        return "沒有收到 ESP32 的 LED 狀態回覆"


# 【11】建立全頁共用的一個儀表板物件，也就是唯一的 UART 使用者
dashboard = IntegratedDashboard()


# 【12】讀取按鈕的回呼：依序讀值、寫 CSV、畫圖、回傳五個畫面輸出
def refresh() -> tuple[str, str, pd.DataFrame, Figure | None, str]:
    # 【12.1】按下讀取按鈕後，先走請求／回應流程取得最新資料。
    row, error = dashboard.read_sensor()

    # 【12.2】讀取失敗時不寫入 CSV 或重畫圖，保留既有畫面並顯示原因。
    if error:
        return "—", "—", pd.DataFrame(), None, f"讀取失敗：{error}"

    # 【12.3】成功後才依序保存資料、產生圖表，再把五個輸出值交回 Gradio。
    dashboard.append_csv(row)
    data, figure = dashboard.dataframe_and_chart()

    return f"{row['temp_c']:.1f} °C", f"{row['humidity']:.1f} %", data, figure, "已寫入 CSV 並更新圖表"


# 【13】建立 Gradio 元件；此區塊只描述畫面，不直接讀取 UART
with gr.Blocks(title="整合環境看板") as demo:
    # 【13.1】先建立標題；此區塊只描述畫面，不直接讀取 UART。
    gr.Markdown("# 整合環境看板")

    # 【13.2】同一列放置最新溫度與濕度的文字元件。
    with gr.Row():
        temperature = gr.Textbox(label="最新溫度", value="—")
        humidity = gr.Textbox(label="最新濕度", value="—")

    # 【13.3】建立讀取、資料呈現、圖表與 LED 控制元件，等待事件觸發後更新。
    read_button = gr.Button("讀取並記錄資料", variant="primary")
    table = gr.Dataframe(label="最近 20 筆 CSV 資料", interactive=False)
    chart = gr.Plot(label="溫度與濕度趨勢")

    with gr.Row():
        led_on = gr.Button("LED 開啟")
        led_off = gr.Button("LED 關閉")

    status = gr.Textbox(label="狀態")

    # 【14】把按鈕事件連到函式，並指定函式回傳值要更新的元件
    # 【14.1】讀取按鈕的五個輸出順序，必須與 refresh() 的回傳值順序相同。
    read_button.click(refresh, outputs=[temperature, humidity, table, chart, status])

    # 【14.2】lambda 只包住不同參數；真正的序列埠控制仍由同一個 set_led 函式處理。
    led_on.click(lambda: dashboard.set_led(True), outputs=status)
    led_off.click(lambda: dashboard.set_led(False), outputs=status)


# 【15】只在 localhost 啟動；無論如何結束都嘗試釋放 COM 埠
try:
    # 【15.1】只在本機啟動 Gradio 網頁，程式會持續執行直到使用者停止它。
    demo.launch(server_name="127.0.0.1", share=False)
finally:
    # 【15.2】無論正常結束或 Ctrl+C 中斷，都嘗試釋放序列埠。
    dashboard.close()
```

## 出錯時先看哪裡

| 看到的現象 | 第一個檢查位置 | 原因 |
| --- | --- | --- |
| LCD 顯示讀值，但按網頁讀取後逾時 | Python 的 COM 埠、韌體 `readSerialCommands()` | 感測與 LCD 已可運作，問題多半在雙向 UART |
| 網頁顯示新數值，但沒有 CSV 或圖表 | `append_csv()`、資料夾權限、`dataframe_and_chart()` | UART 與 `refresh()` 已收到資料 |
| LED 有亮滅，但網頁沒有狀態文字 | `sendLedStatus()`、`set_led()` 的 `status` 篩選 | 命令可能已到 ESP32，但回覆格式或讀取不同步 |
| Python 顯示 COM 埠被占用 | Arduino 序列監控或另一支 Python 程式 | 同一個 COM 埠不能同時由兩個程式開啟 |

## 何時使用、何時不要使用

| 情境 | 建議 |
| --- | --- |
| 想理解第八節一筆資料怎麼變成 CSV、圖表與網頁 | 依本頁的資料流與責任表閱讀主線程式 |
| 想知道為什麼 `read_now` 不直接讀下一行 | 閱讀 UART 緩衝區延伸頁 |
| 想修改套件 API 或練習 Python 語法 | 等第二階段的 Python 與套件實作系列；本頁不提供修改任務 |
| 想把儀表板做成公開正式網站 | 不在本頁範圍；主線 Gradio 仍是 localhost 原型 |

## 常見誤解

### 「Gradio 自己會讀取 ESP32」

不會。Gradio 只在按鈕事件發生時呼叫 Python 函式並顯示回傳結果。真正開啟 COM 埠、讀 JSON 和寫 CSV 的是 `IntegratedDashboard`。

### 「`refresh()` 成功就代表每一段都不可能出錯」

不一定。`refresh()` 先取得資料，再寫 CSV、讀取 DataFrame、建立圖表。每一段都有自己的錯誤來源，因此要按照資料流找第一個沒有得到預期結果的位置。

### 「LED 按鈕也應該新增一筆感測資料」

不是。LED 按鈕的工作是送出 `led` 命令並等待 `status` 回覆；感測資料由「讀取並記錄資料」按鈕的 `read_now` 流程處理。

## 重點整理

- ESP32 管理 DHT11、LCD、UART 命令與 LED；Python 管理 CSV、圖表與 Gradio。
- `read_sensor()` 先取得可接受的資料列，`refresh()` 再依序寫 CSV、更新圖表與元件。
- Gradio 的回傳值順序必須和 `outputs` 順序相同。
- 從資料流找第一個失敗位置，比同時修改多段程式更有效。
