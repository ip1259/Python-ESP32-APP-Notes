# 延伸選讀：74HC595 與裸 8×8 點陣掃描導讀

> 對應主線：[74HC595：辨識並驅動裸 8×8 點陣](06-74hc595-8x8點陣.md)

這一頁解讀主線的愛心圖樣，理解一列資料如何透過 74HC595 顯示在裸點陣。

## 讀完後你會知道

- `data`、`clock`、`latch` 三條線如何把八個位元送到輸出腳。
- 為什麼掃描時要先關閉所有列，再設定欄資料。
- `ROW_ON_HIGH`、列欄順序與位元順序如何影響反相或鏡像。

## 先知道這件事

主線已先用單顆 LED 驗證 74HC595，並以低電流測試記錄自己的點陣列線、欄線與極性。以下快照對應 `matrix_heart.ino`；`ROW_PINS` 與 `ROW_ON_HIGH` 必須仍以自己的已確認紀錄為準。

## 程式的資料流

```text
HEART 的一列位元 → writeColumns() → 74HC595 Q0～Q7
                         ↑
ROW_PINS 選擇目前這一列 ← scanFrame()
```

## 完整程式導讀

執行位置：Arduino IDE／ESP32
來源檔案：`matrix_heart.ino`

```cpp linenums="1"
// 【1】74HC595 的序列資料、時脈與鎖存控制線
const int DATA_PIN = 23;
const int CLOCK_PIN = 18;
const int LATCH_PIN = 5;

// 【2】ESP32 直接控制的八條列線
const int ROW_PINS[8] = {13, 14, 16, 17, 19, 25, 26, 27};

// 【3】列線接正極才亮時為 true；接 GND 才亮時為 false
const bool ROW_ON_HIGH = true;

// 【4】每個 byte 是一列，從左到右對應 bit 7 到 bit 0
const byte HEART[8] = {
  B00000000,
  B01100110,
  B11111111,
  B11111111,
  B01111110,
  B00111100,
  B00011000,
  B00000000,
};

// 【5】把目前列需要亮起的欄資料送到 74HC595
void writeColumns(byte pixels) {
  byte outputs = 0;

  // 【5.1】逐欄讀取圖樣位元，依極性組合真正輸出值
  for (int column = 0; column < 8; column++) {
    bool pixel_on = pixels & (B10000000 >> column);  // 註5.1.1
    bool column_on_high = !ROW_ON_HIGH;  // 註5.1.2

    if (pixel_on == column_on_high) {  // 註5.1.3
      outputs |= (B00000001 << column);
    }
  }

  // 【5.2】鎖存前移出八個位元，最後一起更新 Q0～Q7
  digitalWrite(LATCH_PIN, LOW);
  shiftOut(DATA_PIN, CLOCK_PIN, MSBFIRST, outputs);  // 註5.2.1
  digitalWrite(LATCH_PIN, HIGH);
}

// 【6】將所有列關閉，避免換列時同時點亮造成鬼影
void allRowsOff() {
  int row_off_level = ROW_ON_HIGH ? LOW : HIGH;

  for (int row = 0; row < 8; row++) {
    digitalWrite(ROW_PINS[row], row_off_level);
  }
}

// 【7】依序顯示八列，形成一個完整畫面
void scanFrame(const byte frame[8]) {
  int row_on_level = ROW_ON_HIGH ? HIGH : LOW;

  for (int row = 0; row < 8; row++) {
    // 【7.1】安全的換列順序：關列、寫欄、開一列
    allRowsOff();
    writeColumns(frame[row]);
    digitalWrite(ROW_PINS[row], row_on_level);
    delayMicroseconds(900);
  }

  allRowsOff();
}

// 【8】設定三條控制線與八條列線為輸出，並建立全暗初始狀態
void setup() {
  pinMode(DATA_PIN, OUTPUT);
  pinMode(CLOCK_PIN, OUTPUT);
  pinMode(LATCH_PIN, OUTPUT);

  for (int row = 0; row < 8; row++) {
    pinMode(ROW_PINS[row], OUTPUT);
  }

  allRowsOff();
  writeColumns(B00000000);
}

// 【9】不斷重複掃描，讓眼睛看見完整愛心
void loop() {
  scanFrame(HEART);
}
```

## 範例程式中的位元運算

 範例函式`writeColumns()`中使用到了位元運算。這個函式的工作不是直接點亮整個點陣，而是把「目前這一列」哪些欄位該亮，整理成 74HC595 要輸出的八個位元。

先以 `HEART` 的第二列 `B01100110` 為例。由左到右，它代表：

```text
欄位位置：  0 1 2 3 4 5 6 7
像素資料：  0 1 1 0 0 1 1 0
畫面結果：  . X X . . X X .
```

### 註 5.1.1：`pixels & (B10000000 >> column)`

```cpp
bool pixel_on = pixels & (B10000000 >> column);
```

這一行要回答的是：「目前正在檢查的 `column`，它的像素是亮還是不亮？」

`B10000000` 是只有最左邊一個位元為 `1` 的遮罩。`>> column` 表示把這個 `1` 向右移動 `column` 格。例如：

| `column` | `B10000000 >> column` 的結果 | 正在查看的欄位 |
| ---: | --- | --- |
| 0 | `B10000000` | 最左邊第 0 欄 |
| 1 | `B01000000` | 第 1 欄 |
| 2 | `B00100000` | 第 2 欄 |
| 7 | `B00000001` | 最右邊第 7 欄 |

符號 `&` 是「逐位元且」。只有 `pixels` 和遮罩在同一個位置都為 `1` 時，結果才不是 0。以第二列 `B01100110` 為例，當 `column` 是 1：

```text
pixels:  B01100110
遮罩:    B01000000
結果:    B01000000  → 不是 0，所以 pixel_on 是 true
```

當 `column` 是 0 時，遮罩為 `B10000000`；兩者沒有同時為 `1` 的位置，結果為 0，所以 `pixel_on` 是 `false`。因此迴圈每跑一次，就能依序讀出一欄的亮、滅狀態。

### 註 5.1.2：`!ROW_ON_HIGH`

```cpp
bool column_on_high = !ROW_ON_HIGH;
```

`!` 是「不是」的意思，會把布林值反轉：`!true` 變成 `false`，`!false` 變成 `true`。

一顆 LED 要亮，列線與欄線必須形成正確的電位差。若目前點陣是「列線接 HIGH 才啟用」，也就是 `ROW_ON_HIGH = true`，那麼亮起的欄線就要是 LOW。因此 `!ROW_ON_HIGH` 會得到 `false`，用來表示「這個欄位亮起時，74HC595 應輸出 LOW」。反過來，若列線接 LOW 才啟用，亮起的欄線就要 HIGH。

| `ROW_ON_HIGH` | 目前列的啟用電位 | `column_on_high` | 亮起欄位的電位 |
| --- | --- | --- | --- |
| `true` | HIGH | `false` | LOW |
| `false` | LOW | `true` | HIGH |

### 註 5.1.3：`pixel_on == column_on_high`

```cpp
if (pixel_on == column_on_high) {
  outputs |= (B00000001 << column);
}
```

`==` 是「是否相同」的比較。這裡不是把值存進去，而是在判斷兩個 `true`／`false` 是否一致。

`outputs` 的每一個位元代表 74HC595 的一個輸出腳：最右邊的 bit 0 對應 `Q0`，bit 1 對應 `Q1`，依此到 bit 7 對應 `Q7`。`B00000001 << column` 會把唯一的 `1` 移到目前欄位的位置；`|=` 則把這個 `1` 保留到 `outputs` 中，不會清除前面欄位已整理好的結果。

以 `ROW_ON_HIGH = true` 為例，`column_on_high` 是 `false`。第二列的欄位 0 是滅的，所以 `pixel_on` 也是 `false`；兩者相同，程式便把輸出 bit 0 設為 `1`，讓 `Q0` 為 HIGH。欄位 1 是亮的，`pixel_on` 是 `true`，兩者不同，程式不設 bit 1，讓 `Q1` 保持 LOW。這正好符合「列線 HIGH 時，亮起欄線要 LOW」的極性需求。

```text
畫面要亮的欄：      . X X . . X X .
74HC595 輸出：     1 0 0 1 1 0 0 1
```

上方輸出的閱讀方向要注意：程式用 bit 0 對應第 0 欄；實際接線順序仍須和你的欄線紀錄一致。

### 註 5.2.1：`shiftOut(DATA_PIN, CLOCK_PIN, MSBFIRST, outputs)`

```cpp
shiftOut(DATA_PIN, CLOCK_PIN, MSBFIRST, outputs);
```

74HC595 只有 `DATA_PIN` 和 `CLOCK_PIN` 兩條線用來接收八個位元。

`shiftOut()` 會自動重複八次以下行為：把一個位元放到 `DATA_PIN`，再讓 `CLOCK_PIN` 產生一次時脈。`MSBFIRST` 表示先送最高位元 bit 7，最後送最低位元 bit 0。

在這一行之前，`digitalWrite(LATCH_PIN, LOW)` 先暫停更新可見的 `Q0`～`Q7`；八個位元都送完後，`digitalWrite(LATCH_PIN, HIGH)` 才讓它們同時更新。這就是鎖存的作用：避免資料還在一個一個移入時，點陣先顯示不完整的欄位組合。

## 掃描順序為什麼重要

每次只有一列被啟用。`writeColumns()` 先將這一列的八個像素轉成輸出位元，`scanFrame()` 再短暫啟用該列；接著立刻換下一列。重複得夠快時，視覺暫留會把八列看成完整圖樣。

| 看到的現象 | 優先判讀的地方 |
| --- | --- |
| 全暗 | 先確認單顆 LED 測試、極性與列欄紀錄。 |
| 左右鏡像 | 查看 `HEART` 的 bit 7 到 bit 0 與欄線順序。 |
| 上下顛倒 | 查看 `ROW_PINS` 的 Row 0 到 Row 7 對應。 |
| 鬼影或閃爍 | 查看「關列、寫欄、開一列」的掃描順序與迴圈是否有長時間等待。 |

## 常見誤解

### 「一個 byte 會同時控制整個點陣」

不是。`HEART` 的一個 byte 只描述目前啟用那一列的八個欄位；完整圖樣需要八列輪流顯示。

### 「把 `ROW_ON_HIGH` 改掉可以修正所有問題」

不是。它只處理已確認的極性。鏡像、上下顛倒與位置錯誤通常仍要回到列欄實體接線與紀錄比對。

## 重點整理

- 74HC595 用移位與鎖存，將三條控制線換成八條輸出。
- 每一列的圖樣由一個 byte 表示。
- 掃描順序是先關閉所有列、設定欄資料、只啟用一列。
- `ROW_ON_HIGH`、列欄順序與位元方向必須和實測紀錄一致。
