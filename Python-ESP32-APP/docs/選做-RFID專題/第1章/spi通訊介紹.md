# 資訊補充：SPI 怎麼讓 ESP32 和 RC522 合作

SPI 是 ESP32 和 RC522 之間的一組「有共同節拍的對話線」，讓兩個裝置知道什麼時候傳送、什麼時候接收。

!!! info "這是資訊補充"

    本頁只幫助你理解第 1 章的接線與程式，不需要接硬體、不需要執行程式，也不會讀取卡片資料。

## 你會了解什麼

- 用日常方式理解 SPI 為什麼需要多條線一起合作。
- 分辨 `SCK`、`MOSI`、`MISO`、`SS` 與 `RST` 各自負責什麼。
- 知道 RC522 板上標示的 `SDA`，在這裡其實是 SPI 的 `SS`，不是 I2C 的資料線。
- 理解 SPI 只負責 ESP32 與 RC522 之間的溝通，不等於讀取 UID 或判定卡片能否通行。

## 先看整體：誰在和誰說話？

第 1 章的 RC522 有兩段不同的溝通：

```text
練習卡 ～～近距離感應～～> RC522
ESP32  <──SPI 訊號線──>  RC522
```

練習卡靠近時，是 RC522 用近距離感應和卡片溝通；ESP32 不會直接和卡片說話。ESP32 只透過 SPI 線路詢問 RC522「附近有沒有新卡」、「這次讀取是否成功」。

可以把 ESP32 想成櫃檯人員，RC522 像站在門口的感應器。感應器負責感應卡片；櫃檯人員則透過幾條固定的內線，向感應器確認狀態。

## SPI 像有節拍的短對話

兩個人用對講機時，除了要知道誰在說話，也要知道何時輪到自己回應。SPI 用幾條線把這件事分開處理：一條線提供共同節拍、兩條線分別負責去程和回程，另一條線決定這次要找哪個裝置。

```text
ESP32：先指定要找 RC522，再用共同節拍送出詢問
RC522：跟著同一個節拍，把結果回傳給 ESP32
```

這不是網路連線，也沒有網址、帳號或雲端服務。它是開發板和附近模組之間很短距離的實體線路溝通。

## 每條線在做什麼

| 名稱 | 日常比喻 | 在第 1 章的實際工作 |
| --- | --- | --- |
| `SCK` | 大家一起聽的拍子 | ESP32 提供時脈，讓雙方知道何時送出或接收一小段資料。 |
| `MOSI` | 櫃檯對感應器說話的方向 | ESP32 將詢問或設定傳給 RC522。名稱中的 `O` 可先記成 ESP32 的「送出」。 |
| `MISO` | 感應器回覆櫃檯的方向 | RC522 把讀卡相關的結果回傳給 ESP32。名稱中的 `I` 可先記成 ESP32 的「收到」。 |
| `SS` | 點名要找誰 | ESP32 指定這次要和 RC522 溝通。若日後同一組線接了多個 SPI 裝置，這條線可避免大家同時回話。 |
| `RST` | 請感應器重新開始 | ESP32 用來重新設定 RC522；它不是 SPI 資料線，但第 1 章的 RC522 需要它。 |

第 1 章把這些線接到下列腳位：`SCK` 是 `GPIO 18`、`MOSI` 是 `GPIO 23`、`MISO` 是 `GPIO 19`、`SS` 是 `GPIO 5`，`RST` 是 `GPIO 22`。實際接線請回到[第 1 章：RC522 RFID 與 SPI](index.md)的表格，不需要因為閱讀本頁而重新接線。

## 為什麼要分成 `MOSI` 和 `MISO`？

把它想成一條送件通道和一條回件通道：

```text
ESP32 --MOSI--> RC522
ESP32 <--MISO-- RC522
```

ESP32 可以送出問題，RC522 也能回傳結果。這就是第 1 章會同時使用 `MOSI` 和 `MISO` 的原因。只有單方向資料線的裝置，不能把讀卡結果沿同一種方式送回 ESP32。

## `SDA` 為什麼不是 I2C 的 `SDA`？

同一個縮寫可能被不同模組用來表示不同意思。RC522 板上的 `SDA` 通常表示 SPI 的 `SS`，也就是「這次指定哪個裝置」的線；在第 1 章接到 `GPIO 5`。

主線 LCD 的 I2C `SDA` 才是 I2C 資料線，接到 `GPIO 21`。兩者名稱看起來相同，卻不是同一條線，也不能互換。

| 裝置上的標示 | 使用的溝通方式 | 第 1 章或主線的接法 |
| --- | --- | --- |
| RC522 的 `SDA`／`SS` | SPI 的片選線 | `GPIO 5` |
| LCD 的 `SDA` | I2C 的資料線 | `GPIO 21` |

## SPI 和安全讀卡的關係

SPI 只能讓 ESP32 與 RC522 交換訊號，例如「有沒有偵測到新卡」或「本次讀取是否成功」。它沒有決定卡片是否屬於某個人，也沒有決定能不能開門。

第 1 章只顯示固定的「已讀到練習卡」文字，不讀取或輸出完整 UID。後續專題處理名單、狀態與資料保護時，仍要遵守第 0 章的資料最小化原則；SPI 本身不會替資料加密或保護卡片資訊。

## 常見疑問

### `SCK` 是不是在傳卡片資料？

不是。`SCK` 像共同節拍，只告訴雙方何時交換資料；真正的去程和回程資料分別走 `MOSI` 與 `MISO`。

### 沒有接 `IRQ`，RC522 還能讀卡嗎？

可以。第 1 章的程式會持續詢問 RC522 是否有新卡，因此不需要用 `IRQ` 主動通知。`IRQ` 是另一種通知方式，本章不使用它。

### `SS` 是不是和 74HC595 的鎖存腳一樣？

不是。`SS` 是選擇目前要對話的 SPI 裝置；74HC595 的鎖存腳則是在指定時間把已收到的資料顯示到輸出腳。兩者都像「指定時機」的訊號，但工作不同。

## 重點整理

- SPI 是 ESP32 和 RC522 之間的實體線路溝通；卡片則由 RC522 近距離感應。
- `SCK` 管節拍，`MOSI` 從 ESP32 前往 RC522，`MISO` 從 RC522 回到 ESP32，`SS` 指定要對話的裝置。
- RC522 的 `SDA` 是 SPI 的 `SS`，接 `GPIO 5`；它不是 LCD 的 I2C `SDA`。
- SPI 能傳遞讀卡狀態，但不能判定真實身分、保護 UID 或控制實體設備。
