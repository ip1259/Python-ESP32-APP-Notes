# 資訊補充：MFRC522 函式庫怎麼使用

`MFRC522` 函式庫把 ESP32 與 RC522 之間繁瑣的 SPI 溝通包成容易呼叫的工具，讓程式能依固定順序確認「有新卡靠近」和「本次讀取成功」。

!!! info "這是資訊補充"

    本頁幫助你看懂第 1 章的程式，不需要新增硬體、帳號或網路設定。不讀本頁也能完成[第 1 章首頁](index.md)的受控讀卡操作。

## 你會學到什麼

- 說出 `MFRC522` 函式庫和 `SPI` 函式庫各自負責的工作。
- 依順序理解建立讀卡機、初始化、等卡片、讀取與收尾的作用。
- 分辨本課的固定成功文字，和官方診斷／讀寫範例的不同用途。
- 說出讀取、認證與寫入資料區塊在完整流程中的先後關係。

## 開始前

- 本頁對應[第 1 章：RC522 RFID 與 SPI](index.md)已驗證的 `MFRC522 1.4.12` 與 NodeMCU-32S 接線。
- 只閱讀程式概念時不需接線；若回到第 1 章實作，必須使用明確獲授權的練習卡，且 RC522 只能接 `3.3V`。
- 若日後進行讀寫練習，只能使用課程提供、近乎空白且不含敏感資料的通用練習卡。這一頁目前只解釋官方讀寫範例，不是可直接操作的寫卡教材。

!!! warning "卡片資料與安全限制"

    UID 只是卡片可讀取的識別資料，不能可靠證明持卡者身分。官方 README 也明確提醒 UID 不適合安全用途；本課的讀卡確認不列印、保存或傳送完整 UID，也不控制實體設備。

!!! danger "卡片使用範圍：只用課程提供的通用練習卡"

    悠遊卡、信用卡、金融卡、學生證、公司門禁卡、社區感應扣和來歷不明的卡片，都不是本課測試目標。不同卡片技術下，模組可能感應到卡片、回報部分資訊，甚至有人嘗試讀寫；一律不得測試、複製、修改、截圖或保存。它們可能含有交易紀錄、儲值價值、個人資料或受保護的系統資料。悠遊卡官方也將交易紀錄視為個人交易隱私並提供[正式查詢管道](https://www.easycard.com.tw/faq?keywords=%E8%A8%98%E5%90%8D)；請使用該管道處理自己的票卡資料，而不是用本課 RC522 嘗試存取。

## 函式庫像什麼

可以把 SPI 想成 ESP32 和 RC522 之間的線路與共同節拍；`MFRC522` 函式庫則像翻譯員，替你把「開始使用讀卡機」、「附近有沒有新卡」、「這次能不能讀取」這些需求，轉成 RC522 聽得懂的 SPI 訊號。

- `#include <SPI.h>`：使用 Arduino 已提供的 SPI 工具，準備 ESP32 與 RC522 的共用通訊線。
- `#include <MFRC522.h>`：加入 `MFRC522` 函式庫，讓程式可使用 RC522 的初始化與讀卡功能。

官方專案說明這個函式庫是給 RC522 類型模組使用，微控制器和讀卡機之間走 SPI；RC522 與卡片之間則是近距離的 `13.56 MHz` 無線通訊。[官方 README](https://github.com/miguelbalboa/rfid) 也說明此專案功能已凍結、維護較少，因此本課只固定使用已驗證的版本與流程，不把它當成新的安全門禁方案。

## 第 1 章使用順序

第 1 章的程式和官方 `DumpInfo` 範例有相同的基本骨架，但移除了會顯示卡片資料的部分：

```text
設定腳位 → 建立 rfid → 啟用 SPI → 初始化 RC522
→ 等待新卡 → 讀取本次卡片 → 顯示固定成功文字 → 結束本次通訊
```

下表把每個主要呼叫拆開說明。`bool` 可以先理解成「是／否」：函式回傳 `true` 表示成功或符合條件，`false` 表示沒有成功或不符合條件。

| 寫法 | 傳入什麼 | 得到什麼 | 在本章的用途 |
| --- | --- | --- | --- |
| `MFRC522 rfid(SS_PIN, RST_PIN);` | 片選腳位 `GPIO 5` 與重設腳位 `GPIO 22` | 一個名為 `rfid` 的讀卡機物件 | 讓後面的 `rfid.函式()` 知道要操作哪個 RC522，以及使用哪兩個可設定腳位。 |
| `SPI.begin();` | 不需額外值 | 不回傳資料 | 啟用 ESP32 的預設 SPI 介面，讓 `SCK`、`MOSI`、`MISO` 開始可用。 |
| `rfid.PCD_Init();` | 不需額外值 | 不回傳資料 | 初始化 RC522 讀卡機。`PCD` 是讀卡機本體的名稱，可先把它理解成 RC522 模組。 |
| `rfid.PICC_IsNewCardPresent()` | 不需額外值 | `true` 或 `false` | 檢查附近是否有一張「新靠近」的卡；沒有時立刻回到迴圈開頭，避免一直做同樣的讀取。 |
| `rfid.PICC_ReadCardSerial()` | 不需額外值 | `true` 或 `false` | 嘗試讀取本次卡片的基本通訊資料；本課只用成功與否，不取用其 UID。`PICC` 可先理解成靠近讀卡機的卡片或感應扣。 |
| `rfid.PICC_HaltA();` | 不需額外值 | 不回傳資料 | 告訴這張卡本次通訊結束，讓它移開後能被當成下一次新卡。 |
| `rfid.PCD_StopCrypto1();` | 不需額外值 | 不回傳資料 | 清理讀卡機本次可能使用的通訊加密狀態；即使本課不讀卡片區塊，仍在成功後呼叫它完成收尾。 |

`PICC_IsNewCardPresent()` 和 `PICC_ReadCardSerial()` 都只回答「是否偵測到／是否成功」。它們不等於授權判斷；第 1 章的「已讀到練習卡」只是在確認硬體流程，並不判斷真實身分。

## 讀取、認證與寫入：完整流程長什麼樣子

第 1 章只做到「確認有卡、確認本次讀取成功」；這是完整卡片資料操作的前半段。官方 `ReadAndWrite` 範例接著處理的是 MIFARE Classic 卡片的資料區塊。可以把它想成有鎖的置物櫃：先確認是哪一個櫃子，再用正確鑰匙打開，才讀或放入內容。

```text
偵測新卡 → 選取卡片 → 確認卡片類型 → 取得該區塊的使用權
→ 讀取區塊 或 寫入區塊 → 再讀一次確認 → 結束本次通訊
```

| 階段 | 官方函式或資料 | 傳入什麼 | 回傳什麼 | 白話作用 |
| --- | --- | --- | --- | --- |
| 確認類型 | `PICC_GetType(rfid.uid.sak)` | 卡片回報的 `sak` 資訊 | `PICC_Type` 卡片類型 | 確認後面的讀寫方式是否適用這張卡。 |
| 準備鑰匙 | `MFRC522::MIFARE_Key key` | 一組金鑰資料 | 一個保存金鑰的資料結構 | 這是進入受保護區塊前要準備的「鑰匙」。範例中的出廠預設值不代表安全，也不應拿來猜測別人的卡。 |
| 取得區塊使用權 | `PCD_Authenticate(...)` | 金鑰種類、控制區塊位置、金鑰與本次卡片資料 | `StatusCode`，`STATUS_OK` 表示成功 | 確認程式有權使用指定區塊；不是「使用者身分驗證」。失敗就停止，不要反覆嘗試不同金鑰。 |
| 讀取資料 | `MIFARE_Read(blockAddr, buffer, &size)` | 區塊位置、接收資料的陣列、可用空間大小 | `StatusCode`；成功時資料放入 `buffer` | 把指定區塊的位元組放進程式的暫存空間。讀到不代表可以公開、保存或轉傳。 |
| 寫入資料 | `MIFARE_Write(blockAddr, dataBlock, 16)` | 區塊位置、要寫入的 16 個位元組 | `StatusCode` | 將固定長度資料寫入指定區塊。只能對課程提供的空白通用練習卡使用；位置或內容不確定就停止。 |
| 再次確認 | `MIFARE_Read(...)` | 同一區塊與暫存空間 | `StatusCode` 與最新資料 | 讀回剛寫入的結果，確認寫入是否符合預期。 |

官方範例會把資料內容印到序列監控，方便了解每一個位元組。本課目前不提供這段操作，因為需要先在指定練習卡與課程硬體上驗證資料區塊、金鑰、寫入結果與復原方式；在完成前，不要自行替換第 1 章的安全讀卡程式。

## 和官方範例的差別

官方的 [`DumpInfo`](https://github.com/miguelbalboa/rfid/tree/master/examples/DumpInfo) 範例用相同順序做 `SPI.begin()`、`PCD_Init()`、偵測新卡和讀取卡片，之後會把 UID、卡片類型與可讀資料輸出到序列監控。這適合查硬體與卡片資訊，但不適合本課的資料最小化範圍。

官方的 [`ReadAndWrite`](https://github.com/miguelbalboa/rfid/tree/master/examples/ReadAndWrite) 範例還會驗證卡片類型、使用金鑰讀取區塊，並寫入 MIFARE Classic 的資料區。它能幫助理解完整流程，但原始碼已明示會寫入卡片；在本課讀寫實測完成前，請不要自行執行，尤其不能對悠遊卡、信用卡、學生證、門禁卡或其他非課程提供的卡片使用。

| 目的 | 本課第 1 章程式 | 官方 `DumpInfo` | 官方 `ReadAndWrite` |
| --- | --- | --- | --- |
| 確認 SPI 與 RC522 可溝通 | 使用 | 使用 | 使用 |
| 顯示 UID 或卡片資料 | 不使用 | 使用 | 使用 |
| 讀取卡片資料區塊 | 不使用 | 可能使用 | 使用 |
| 寫入卡片 | 不使用 | 不使用 | 使用 |
| 適合本課目前的受控讀卡 | 是 | 僅供理解診斷用途 | 僅供理解完整流程 |

## 成功的樣子

回到第 1 章的程式後，序列監控只會看到 `RC522 已就緒，請靠近練習卡`、`已讀到練習卡` 與移開卡片的提示。看不到 UID、卡片類型、資料區塊或寫入訊息，正是本章有遵守資料最小化的結果。

## 常見問題

### 為什麼明明呼叫了「讀取」，卻不印出資料？

`PICC_ReadCardSerial()` 的工作是完成本次卡片選取與讀取；讀到的資料會留在函式庫物件裡。第 1 章刻意不讀取 `rfid.uid`，只根據函式回傳的成功與否顯示固定文字。

### 可以改用官方 `DumpInfo` 找問題嗎？

先依第 1 章的接線、供電與常見問題檢查。`DumpInfo` 會把完整 UID 和更多卡片資訊印出來；若因硬體排查確實需要研究官方範例，請只使用你有權使用的練習卡，且不要保存、截圖或分享輸出。排查結束後回到本章的受控程式。

### 為什麼同一張卡要移開後再靠近？

本章用 `PICC_IsNewCardPresent()` 避免卡片一直放在讀卡機上時重複觸發。移開後再靠近，才會成為下一次可觀察的「新卡」事件。

## 重點整理

- `SPI` 負責 ESP32 和 RC522 的通訊線；`MFRC522` 函式庫把讀卡機操作整理成可呼叫的函式。
- 第 1 章的順序是建立物件、啟用 SPI、初始化、偵測、讀取、顯示固定文字與收尾。
- 完整資料操作還會經過卡片類型、區塊使用權、讀取或寫入與讀回確認；只有課程提供的空白通用練習卡可作為未來受控讀寫練習目標。
- 悠遊卡、信用卡、學生證、門禁卡等可能承載個資或交易資料，必須避開並使用其正式服務管道處理。
