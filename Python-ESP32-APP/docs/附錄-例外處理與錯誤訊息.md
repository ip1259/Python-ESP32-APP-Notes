# 延伸選讀：例外處理與錯誤訊息

外部檔案或資料格式出問題時，讓程式指出原因並安全結束，而不是只顯示模糊的「失敗」。

## 你會學到什麼

- 使用 `try` 與 `except` 處理可預期的讀檔與資料格式錯誤。
- 分辨 `FileNotFoundError`、`json.JSONDecodeError` 和 `UnicodeDecodeError` 的意義。
- 在函式或類別發現無法自行決定的資料問題時，使用 `raise` 將明確錯誤交給上層處理。
- 用 `else` 處理成功結果、用 `finally` 放置一定會執行的收尾動作。
- 使用 `with` 讀取檔案，讓檔案資源在結束後自動釋放。

## 開始前

- 建議先完成[用 uv 建立 Python 虛擬環境](01-uv與虛擬環境.md)，並能在自己的練習資料夾執行 `uv run python`。
- 本頁連回[UART：讓 Python 與 ESP32 雙向通訊](03-uart-python-esp32.md)與[將感測資料存成 CSV 並繪製趨勢圖](04-python-感測資料視覺化.md)：它們都會遇到外部資料不能直接相信的情況。
- 範例只讀取固定文字或練習檔名，不連接 ESP32 或開啟 COM 埠。
- 讀取失敗時，先保留原始檔案與錯誤訊息；不要為了排錯刪除或覆寫你已收集的感測資料。

## 成功的樣子

執行完整範例後，終端機會依序顯示：

```text
找不到檔案：missing_sensor.csv。請確認檔名與目前資料夾。
JSON 格式不正確：請檢查雙引號、逗號與大括號。
溫度超出練習範圍：-80.0°C
文字編碼不正確：請確認檔案是否為 UTF-8。
成功讀取：26.5°C，61.0%
本次讀取流程結束。
```

前三行是刻意建立的受控錯誤；最後兩行表示程式能在成功情境取得資料並完成收尾。

## 先處理一種可預期的錯誤

目的：讀取不存在的檔案時，明確告訴使用者該先檢查什麼。

操作：建立 `exceptions_demo.py`，先貼上並執行下列程式。

```python
# 執行位置：Python／電腦
# 檔名：exceptions_demo.py
from pathlib import Path


missing_path: Path = Path("missing_sensor.csv")

try:
    text: str = missing_path.read_text(encoding="utf-8")
    print(text)
except FileNotFoundError:
    print(f"找不到檔案：{missing_path}。請確認檔名與目前資料夾。")
```

預期結果：顯示 `找不到檔案：missing_sensor.csv。請確認檔名與目前資料夾。`。`FileNotFoundError` 表示程式找不到指定位置；先檢查檔名、資料夾和終端機目前位置，不要先假設 ESP32 壞掉。

不要以空白 `except:` 或 `except Exception:` 取代這個例外類別。那會連程式本身的拼字或邏輯問題也一起藏起來，之後更難找到真正原因。

## 函式無法決定時，用 `raise` 向上傳遞

目的：讓驗證函式或類別只負責判斷資料是否符合規則；它不知道介面要顯示什麼、要不要重試或整個流程是否要停止時，不在內部自行猜測處理方式。

操作：在 `exceptions_demo.py` 加入並執行下列程式。

```python
# 執行位置：Python／電腦
# 檔名：exceptions_demo.py
def validate_temperature(temperature_c: float) -> float:
    if not -40.0 <= temperature_c <= 85.0:
        raise ValueError(f"溫度超出練習範圍：{temperature_c}°C")
    return temperature_c


try:
    checked_temperature: float = validate_temperature(-80.0)
    print(f"可使用的溫度：{checked_temperature}°C")
except ValueError as error:
    print(error)
```

預期結果：顯示 `溫度超出練習範圍：-80.0°C`。`validate_temperature()` 能知道數值不合理，卻不知道呼叫它的是終端機、Gradio 介面還是資料儲存流程，因此用 `raise ValueError(...)` 將問題交回呼叫端。上層的 `try`／`except` 再依情境決定顯示友善訊息、停止本次資料處理或要求重新輸入。

這和在函式內直接 `print()` 後回傳假資料不同：`raise` 會中斷目前函式，避免不可信資料繼續送到 CSV、圖表或介面。只有能明確判斷資料違反規則時才使用它；不要把所有未知問題都包成 `ValueError`。

## 將成功與失敗分開處理

目的：只有資料真的讀取並解析成功後，才使用其中的溫度與濕度。

操作：將下列完整程式貼到同一個 `exceptions_demo.py` 後執行。

```python
# 執行位置：Python／電腦
# 檔名：exceptions_demo.py
import json


def load_sensor_row(raw_json: str) -> dict[str, float] | None:
    try:
        data: dict[str, float] = json.loads(raw_json)
        temperature_c: float = data["temperature_c"]
        humidity_pct: float = data["humidity_pct"]
    except json.JSONDecodeError:
        print("JSON 格式不正確：請檢查雙引號、逗號與大括號。")
        return None
    except KeyError as error:
        print(f"缺少必要欄位：{error.args[0]}。")
        return None
    else:
        return {
            "temperature_c": temperature_c,
            "humidity_pct": humidity_pct,
        }


bad_row: dict[str, float] | None = load_sensor_row('{"temperature_c": 26.5')
good_row: dict[str, float] | None = load_sensor_row(
    '{"temperature_c": 26.5, "humidity_pct": 61.0}'
)

if good_row is not None:
    print(f"成功讀取：{good_row['temperature_c']}°C，{good_row['humidity_pct']}%")
```

預期結果：先顯示 JSON 格式不正確的訊息，再顯示 `成功讀取：26.5°C，61.0%`。`try` 放可能失敗的操作；`except` 各自處理已知原因；`else` 只有沒有例外時才回傳可信資料。`dict[str, float] | None` 表示函式成功時回傳感測資料字典，失敗時回傳 `None`；型別提示協助閱讀，但不會自行驗證外部輸入。

## 看懂文字編碼錯誤

目的：知道「檔案存在但文字無法解讀」和「找不到檔案」是不同問題。

操作：在同一個檔案加入並執行下列程式。

```python
# 執行位置：Python／電腦
# 檔名：exceptions_demo.py
invalid_utf8: bytes = b"\xff\xfe"

try:
    invalid_utf8.decode("utf-8")
except UnicodeDecodeError:
    print("文字編碼不正確：請確認檔案是否為 UTF-8。")
```

預期結果：顯示 `文字編碼不正確：請確認檔案是否為 UTF-8。`。真實 CSV 若出現此訊息，先複製一份檔案保留原始資料，再確認匯出程式或文字編輯器選用的編碼；不要直接另存覆寫原檔。

## `finally` 與 `with`：收尾但不掩蓋問題

目的：理解不論成功或失敗都要做的收尾動作，以及檔案資源的安全預設。

操作：執行下列程式，觀察 `finally` 的輸出位置。

```python
# 執行位置：Python／電腦
# 檔名：exceptions_demo.py
from pathlib import Path


csv_path: Path = Path("missing_sensor.csv")

try:
    with csv_path.open("r", encoding="utf-8") as file:
        print(file.readline())
except FileNotFoundError:
    print("練習檔不存在，沒有進行讀取。")
finally:
    print("本次讀取流程結束。")
```

預期結果：先顯示 `練習檔不存在，沒有進行讀取。`，再顯示 `本次讀取流程結束。`。`finally` 無論是否發生例外都會執行；但讀檔時優先用 `with`，它會在區塊結束後關閉檔案，不需要自行呼叫 `close()`。

## 選做練習：找出遺失的欄位

這是延伸練習，不做也不影響主線成果。

目的：確認你能分辨 JSON 格式錯誤與「格式正確、但缺少必要欄位」。

操作：將 `load_sensor_row()` 的輸入改成只有溫度的 JSON，然後執行。

```python
# 執行位置：Python／電腦
# 檔名：exceptions_demo.py
missing_humidity: dict[str, float] | None = load_sensor_row('{"temperature_c": 26.5}')
```

預期結果：顯示 `缺少必要欄位：humidity_pct。`，並且變數值是 `None`。

??? tip "參考作法"
    `load_sensor_row()` 已經處理 `KeyError`，不需要新增寬鬆的 `except Exception:`。如果要使用結果，和完整範例一樣先用 `if missing_humidity is not None:` 確認成功。

## 完成時，應能確認

- 你能說出找不到檔案、JSON 格式錯誤與文字編碼錯誤分別先檢查什麼。
- 你能使用 `try`／`except` 處理一種明確的可預期錯誤。
- 你能說明函式或類別發現資料不符合規則、但無法決定後續操作時，可用 `raise` 將明確例外交給呼叫端處理。
- 你知道 `else` 只在沒有例外時執行，`finally` 則無論成功或失敗都會執行。
- 你讀取檔案時會優先使用 `with`，且不會在讀取錯誤後直接覆寫原始感測資料。

## 常見問題

### 只顯示錯誤訊息，後面的結果沒有出現

先確認輸入資料是否真的合法。範例中的 `bad_row` 是故意錯誤的 JSON；請保留 `good_row` 那筆完整資料，才能看到成功讀取的輸出。

### `KeyError: 'humidity_pct'` 或顯示缺少必要欄位

先檢查 JSON 是否有 `humidity_pct`，以及欄位拼字和大小寫是否一致。不要用預設值假裝資料存在；先確認感測來源是否真的送出該欄位。

### 我想用一個 `except` 處理所有問題

先不要這樣做。請為已知原因使用明確例外類別，例如 `FileNotFoundError` 或 `json.JSONDecodeError`。若是未知問題，保留原始錯誤訊息與操作條件，回到[整合專題故障分流](附錄-故障排除索引.md)找第一個檢查位置。

### 我在函式裡發現不合理資料，卻不知道要顯示什麼訊息

函式或類別若能明確判斷規則被違反，可用 `raise ValueError("原因")` 向上傳遞；由呼叫端用 `try`／`except ValueError` 決定顯示、重試或停止。不要在驗證函式內自行寫 CSV、更新介面或用假值繼續執行。

### 真實 CSV 出現 `UnicodeDecodeError`

先保留原始檔案，確認產生 CSV 的程式與開啟檔案時是否都使用 `utf-8`。若來源無法確認，停止自動處理或覆寫，改用副本測試不同編碼。

## 重點整理

- 例外處理要針對可預期、可修正的原因，不能用寬鬆捕捉掩蓋所有問題。
- `try` 放可能失敗的操作，`except` 處理特定錯誤，`else` 使用成功結果，`finally` 放一定要執行的收尾動作。
- 當函式或類別只知道「資料違反規則」而不知道上層流程該怎麼做時，用 `raise` 傳遞明確例外，由呼叫端處理。
- `with` 是讀寫檔案的安全預設；外部資料失敗時，先保留原始資料和錯誤訊息。
