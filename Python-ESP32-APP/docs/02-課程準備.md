# 課程準備：認識 AIoT 資料流

這一頁會建立本課的共同語言：ESP32 負責硬體，Python 負責資料與畫面，兩者透過 USB 序列埠交換訊息。

## 你會學到什麼

- 說出 ESP32、Python、UART、CSV、Gradio 各自負責的工作。
- 看懂本課從感測器到儀表板的資料流。
- 確認 ESP32 的序列埠與 Arduino IDE 開發板設定。
- 在接線前遵守本課的供電與 GPIO 安全規則。

## 開始前

| 項目 | 需求 |
| --- | --- |
| 前置教材 | [用 uv 建立 Python 虛擬環境](01-uv與虛擬環境.md) |
| 硬體 | NodeMCU-32S 相容 ESP32、USB 資料線、麵包板與杜邦線 |
| 軟體 | Arduino IDE、PowerShell、已建立的 `aiot-course` 專案 |
| 先備能力 | 能上傳 Blink，能讀取 DHT11 |

!!! warning "這一頁不需要把所有元件接上"
    先確認資料流、開發板與序列埠。之後每一單元只加入必要元件，接線前請先拔除 USB 線。

### 額外補充：麵包板供電模組與共地

麵包板供電模組**不在本課每人材料套件內，也不是任何必做單元的必要材料**。以下內容只供日後自行擴充、使用其他外部電源時參考。

它可將 USB 電源提供給麵包板兩側的正、負電源軌。若自行使用，接線前先確認模組跳線選擇的是 `3.3V` 還是 `5V`，也要確認使用的是哪一側電源軌。

當 ESP32 的 USB 與麵包板供電模組同時供電時，必須**共地**：將 ESP32 的 `GND` 接到供電模組負極電源軌（`-`）。共地讓所有元件使用同一個電壓基準；沒有共地時，ESP32 無法可靠判斷感測器或控制訊號的高低電位，可能造成讀值錯誤、控制失敗或通訊不穩。

!!! warning "額外供電不代表 ESP32 GPIO 可以接 5V"
    供電模組可提供 5V，不表示 ESP32 的 GPIO 能承受 5V 訊號。凡是連到 ESP32 GPIO 的訊號線，必須先依該元件的教材確認是否為 3.3V 安全，必要時使用分壓或電平轉換。

## 成功的樣子

完成課程後，資料會依下列方向流動：

```text
DHT11 ──> ESP32 ──USB UART──> Python ──> CSV／Matplotlib／Gradio
              │
              ├──I2C──> LCD1602A
              └──同步序列──> 74HC595 + 8×8 點陣
```

其中，Python 與 ESP32 的核心整合走 USB 線，不需要讓教室電腦連到學生手機熱點。

## 誰負責什麼？

| 元件或工具 | 本課的工作 | 不負責的工作 |
| --- | --- | --- |
| ESP32 | 讀取 DHT11、控制 LED／LCD／點陣、回覆命令 | 執行 Pandas、繪製電腦圖表、執行 Gradio |
| Arduino IDE | 編寫與上傳 ESP32 韌體 | 讀取 Python 的 CSV 或顯示 Gradio 頁面 |
| USB UART | 在 ESP32 與電腦間傳送文字訊息 | 直接控制 GPIO 腳位 |
| Python | 解析訊息、寫 CSV、繪圖、建立 Gradio 儀表板 | 直接把電腦 GPIO 接到 ESP32 元件 |
| Gradio | 在教室電腦本機顯示資料與發出控制命令 | 取代 ESP32 韌體或公開到網際網路 |

!!! note "UART 是什麼？"
    UART 是一種序列通訊方式。USB 線連接 ESP32 與電腦後，Windows 會顯示一個 COM 序列埠。後續 Python 會從這個序列埠讀資料，也會從這裡傳送命令。

## 步驟 1：確認 Arduino IDE 的 ESP32 設定

**目的：** 確認電腦可以把程式上傳到正確的 ESP32。

執行位置：Arduino IDE／電腦

1. 用 USB 資料線連接 ESP32 與電腦。
2. 在 Arduino IDE 開啟「工具」。
3. 將「開發板」選為課堂指定的 NodeMCU-32S 相容 ESP32。
4. 將「連接埠」選為插上 ESP32 後出現的 COM 埠。
5. 開啟你已完成的 Blink 範例並上傳。

預期結果：Arduino IDE 顯示上傳完成，ESP32 的 LED 依 Blink 程式閃爍。

!!! tip "如何找出正確 COM 埠？"
    先記住目前的連接埠清單，拔掉 ESP32 後再看一次；消失的那一個通常就是 ESP32 使用的 COM 埠。請記下它，但不要把 `COM` 號碼寫死在後續程式中。

## 步驟 2：觀察序列監控視窗

**目的：** 知道 ESP32 傳送的文字會在哪裡出現。

執行位置：Arduino IDE／電腦

1. 在 Blink 範例的 `setup()` 中加入序列埠初始化與一行測試文字。
2. 上傳程式後開啟「序列監控視窗」。
3. 將 baud rate 設為與程式相同的值，例如 `115200`。

執行位置：Arduino IDE／ESP32  
檔案：`serial_test.ino`

```cpp
void setup() {
  Serial.begin(115200);
  Serial.println("ESP32 ready");
}

void loop() {
}
```

預期結果：序列監控視窗顯示：

```text
ESP32 ready
```

!!! warning "一次只能有一個程式使用 COM 埠"
    Arduino IDE 的序列監控視窗與 Python 不能同時開啟同一個 COM 埠。下一單元要執行 Python 前，請先關閉序列監控視窗。

## 步驟 3：認識本課的訊息格式

**目的：** 先看懂 Python 與 ESP32 之間會傳送什麼資料。

本課使用「一行一筆 JSON」的訊息。每一筆資料最後都有換行，讓接收端知道這一筆已結束。

ESP32 傳給 Python 的感測資料範例：

```json
{"type":"sensor","temp":25.4,"humidity":61.0}
```

Python 傳給 ESP32 的 LED 命令範例：

```json
{"cmd":"led","value":true}
```

ESP32 執行後的回覆範例：

```json
{"type":"status","led":true,"ok":true}
```

## 接線與安全規則

後續接線時，請遵守以下規則：

| 情境 | 做法 | 原因 |
| --- | --- | --- |
| 接線或拔線 | 先拔除 USB 線 | 避免接錯時持續供電 |
| 每個模組 | 先確認 VCC、GND 與訊號腳 | 模組腳位順序不一定相同 |
| ESP32 GPIO | 使用教材指定的 GPIO | 部分腳位會影響 ESP32 開機或已被其他元件使用 |
| HC-SR04 Echo | 使用分壓或電位轉換 | Echo 可能輸出 5V，不能直接接 ESP32 GPIO |
| 伺服／步進馬達／繼電器 | 等延伸教材確認外部供電與共地後再使用 | ESP32 的 3.3V 腳無法安全供應這些負載 |
| 8×8 裸點陣 | 先做極性與腳位測試 | 不同點陣的列、欄與共陽／共陰可能不同 |

!!! warning "不要同時接滿所有元件"
    本課依單元逐步增加元件。若一次把 LCD、點陣、感測器和馬達都接上，接線錯誤會很難定位。

## 完成時，應能確認

- Arduino IDE 能上傳 Blink 到 ESP32。
- 你知道 ESP32 使用的 COM 埠與設定的 baud rate。
- 序列監控視窗可以顯示 `ESP32 ready`。
- 你能說出 DHT11 資料是由 ESP32 經 USB UART 傳給 Python。
- 小練習輸出的 JSON 同時包含 `cmd` 與 `value` 欄位。

## 常見問題

### Arduino IDE 找不到 ESP32 的 COM 埠

1. 確認 USB 線是資料線，不是只能充電的線。
2. 拔除並重新插上 ESP32，再查看「工具 → 連接埠」。
3. 如果仍沒有新連接埠，請請教師或助教檢查驅動程式與裝置管理員。

### 序列監控視窗顯示亂碼

1. 確認程式中的 `Serial.begin(115200)` 與序列監控視窗都設定為 `115200`。
2. 按一下 ESP32 的重設按鈕，重新觀察輸出。
3. 如果仍是亂碼，先不要改接線，請確認 baud rate。

### Python 無法開啟 COM 埠

1. 關閉 Arduino IDE 的序列監控視窗。
2. 確認沒有另一個 Python 程式正在讀取同一個 COM 埠。
3. 下一單元會用 Python 開啟序列埠；目前只需要記下正確的 COM 埠即可。

## 重點整理

- ESP32 負責硬體讀取與控制，Python 負責資料處理、圖表與 Gradio。
- USB UART 是本課 ESP32 與電腦之間的核心資料通道。
- 每一筆 UART 訊息使用一行 JSON，命令與回覆都能被看懂。
- Arduino IDE 的序列監控視窗與 Python 不能同時使用同一個 COM 埠。
- 接線前先斷電，每次只新增必要元件。
