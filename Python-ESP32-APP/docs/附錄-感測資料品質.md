# 延伸選讀：感測資料品質

> 選讀｜對應主線：[將感測資料存成 CSV 並繪製趨勢圖](04-python-感測資料視覺化.md)、[Gradio：建立本機 AIoT 儀表板](07-gradio-aiot儀表板.md)

本頁說明資料能成功顯示或畫成折線後，仍要檢查哪些條件，才不會過度解讀 DHT11 的短期讀值。

## 讀完後你會知道

- 完整資料列、時間與數值型別為何是畫圖前的基本條件。
- CSV 的資料時間和 DHT11 實際感測時間並不完全相同。
- 十筆資料與儀表板最近 20 筆資料分別能、不能支持什麼觀察。
- 遇到異常時，應先查資料流程的哪一段。

## 先知道這件事

主線已把 `sensor` JSON 寫入 CSV，並以 Pandas 檢查缺值、以 Matplotlib 繪圖；Gradio 則暫存最近 20 筆。這些流程讓資料可見，卻不保證每個數字都能代表長期環境結論。

## 一筆資料經過哪些品質關卡

```text
DHT11 讀值
  ↓ 讀取失敗時，ESP32 傳 error 而非數值
sensor JSON
  ↓ Python 只接受 type = sensor
CSV：timestamp、temp_c、humidity
  ↓ Pandas 轉換時間與數字；無法轉換者成為缺值
完整資料列
  ↓ Matplotlib 折線／Gradio 最近資料
人員判讀
```

重點是每一關都可能排除或改變資料的可用性。圖表沒有顯示某一列，不代表那個環境時刻不存在；它只表示該列不符合主線繪圖所需的完整條件。

## 主線如何判定可繪圖資料

執行位置：Python／電腦  
來源主線檔案：`inspect_sensor_data.py`、`plot_sensor_data.py`

```python linenums="1"
# 【1】讀入 CSV 後，先把三個欄位轉為預期型別。
data["timestamp"] = pd.to_datetime(data["timestamp"], errors="coerce")
data["temp_c"] = pd.to_numeric(data["temp_c"], errors="coerce")
data["humidity"] = pd.to_numeric(data["humidity"], errors="coerce")

# 【2】檢視每個欄位有多少無法使用的值。
print(data.isna().sum())

# 【3】繪圖時只保留時間、溫度、濕度都完整的資料列。
valid_data = data.dropna(subset=["timestamp", "temp_c", "humidity"])

if valid_data.empty:
    raise RuntimeError("沒有可繪圖的完整感測資料")
```

`errors="coerce"` 的意思是：遇到不能轉換的內容時，不假裝它是數字或時間，而是標記為缺值。這讓 `isna().sum()` 能顯示問題規模，也讓 `dropna()` 有一致的排除依據。

## 正確解讀時間、筆數與短期歷史

| 看到的內容 | 可以先說什麼 | 不能直接說什麼 |
| --- | --- | --- |
| CSV 的 `timestamp` | 電腦在這個時間記錄了資料 | 這一定是 DHT11 完成量測的精確時刻 |
| 10 筆主線資料 | 這是一段很短的觀察 | 代表全天、每週或季節趨勢 |
| 一次突然跳動 | 值得回頭檢查感測器位置、手部接近與接線 | 環境一定發生了某個特定事件 |
| Gradio 最近 20 筆 | 可快速查看剛剛的資料變化 | 是完整且永久的歷史紀錄 |
| 一條平順折線 | 完整資料列被依時間畫出 | 感測器已校正且沒有誤差 |

主線的 `timestamp` 是 Python 收到 JSON 後以電腦時間建立，因此它最適合用來排列記錄先後。若要研究精確量測時間、跨裝置比對或長期趨勢，必須重新規劃時鐘來源、資料量與保存方式，超出本課範圍。

## 異常時的第一個檢查位置

| 症狀 | 先檢查 | 原因 |
| --- | --- | --- |
| CSV 只有表頭 | UART 是否真的收到 `type: sensor` | 沒有感測資料就不會寫入列。 |
| 缺值數量增加 | CSV 欄位名、文字格式與轉換結果 | 欄位改名或非數字都可能轉成缺值。 |
| 圖表空白 | `valid_data` 是否為空 | 三個必要欄位至少有一個缺失時會被排除。 |
| 畫面只有少數點 | 是否只按了少數次更新 | Gradio 每次更新只加入一筆。 |
| 讀值不合理 | DHT11 位置、接線與讀取錯誤訊息 | 圖表不會修正來源硬體問題。 |

## 常見誤解

### 「把缺值刪掉就等於修好資料」

刪除不完整列只是避免繪圖把未知值當成有效值；它沒有找回原本缺少的溫度或濕度。看到缺值時，仍應回頭確認 UART 訊息、CSV 欄位或感測器讀取狀態。

### 「儀表板看到資料，就不必保存 CSV」

儀表板的 `deque(maxlen=20)` 只保留程式目前執行期間的最近資料，關閉程式後資料就不在記憶體中。CSV 才是本課用來累積並重畫資料的地方。

## 重點整理

- 可視化前先確認欄位名稱、型別與缺值，避免未知值混入圖表。
- CSV 時間是電腦記錄時間，適合排序先後，不等於精密量測時鐘。
- 短期少量資料適合做觀察，不足以推論長期原因或趨勢。
- Gradio 最近資料與 CSV 長期保存各有用途，不能互相取代。
