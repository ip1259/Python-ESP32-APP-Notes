# ngrok：暫時公開通道的概念

ngrok 可以替本機服務建立一個外部可連線的入口，讓手機或其他裝置在受控測試期間連到電腦上的 API。這個可由網址連入的入口稱為外部端點；HTTPS 則是一種讓資料在傳輸途中較不容易被直接看見或修改的連線方式。

## 你會學到什麼

- 理解 `127.0.0.1`、本機 API、ngrok Agent 與外部端點的關係。
- 知道暫時 HTTPS 網址會改變服務的接觸範圍。
- 分辨傳輸加密、API 權限與資料安全是不同問題。
- 知道何時不應開啟通道，以及測試結束後要停止通道。

## 開始前

- 本頁是概念教材，不提供安裝、登入、authtoken 或開啟通道的操作步驟。
- ngrok 需要外部服務、帳號、網路與目前版本的設定。本頁不包含安裝、登入或開啟通道的操作。
- 不要公開或傳送 authtoken、API token、帳密、私人網址、UID 或個人資料。

## 為什麼手機不能直接用 `127.0.0.1`

在電腦上，`127.0.0.1` 代表「這台電腦自己」。手機開啟相同位址時，指的是手機自己，不是執行 Gateway 的電腦。

ngrok Agent 是在電腦上執行的小程式。它從電腦向 ngrok 服務建立連線，再讓外部端點收到的要求轉回本機 API。

```text
手機或 ESP32
    │
    │ HTTPS 要求
    ▼
ngrok 外部端點
    │
    │ 受控通道
    ▼
電腦上的 ngrok Agent → 本機 Gateway API
```

官方文件將由 Agent 建立、生命週期跟著 Agent 程序的入口稱為 Agent Endpoint。Agent 停止後，這條通道就不再提供服務。

## 暫時網址改變了什麼

| 狀態 | 可連線的範圍 | 要注意的事 |
| --- | --- | --- |
| API 只使用 `127.0.0.1` | 原則上只有同一台電腦 | 適合先確認資料契約與錯誤處理。 |
| 開啟 ngrok 外部端點 | 知道網址且能連網的外部用戶端可能送出要求 | 必須限制資料、功能、時間與可接受的要求。 |
| 停止 Agent 或端點 | 外部要求不再經這條通道抵達本機 API | 測試完成後應回到這個狀態。 |

HTTPS 可以降低資料在傳輸途中被直接看到或修改的風險，但公開 HTTPS 網址本身不是使用者身分驗證，也不是管理權限。Gateway 仍須拒絕錯誤欄位、重複事件與未允許的操作。

## authtoken 是什麼

authtoken 是讓 ngrok Agent 以你的帳號身分連到 ngrok 服務的祕密字串。它不是要放進 ESP32、App、教材範例或截圖的網址參數。

如果 authtoken 出現在公開畫面、程式碼或他人可讀的位置，應停止操作並依服務提供的方式撤銷或更換；不要繼續沿用已暴露的值。

## 在本專題的位置

```text
ESP32 或 App → ngrok 暫時 HTTPS 入口 → Gateway API
```

ngrok 只提供通往 Gateway API 的通道。它不判斷讀卡結果、不保存權威名單，也不取代 Gateway 的資料檢查與權限規則。

使用外部通道前，應先在本機確認固定假資料與 API 錯誤處理。若尚未確認通道如何停止、逾時或 Gateway 中斷時會出現什麼結果，就不要開啟外部端點。

## 安全界線與停止條件

- 只傳送固定假資料；網址、回應或紀錄若出現 UID、帳密、token 或私人資料，立即停止。
- 不把外部端點當作永久網址，也不分享給無關的人。
- 無法確認 Gateway 只提供預期路徑、無法限制管理功能，或不知道如何停止通道時，不開啟外部端點。
- API 無回應、回應事件代號不符或超過等待時間時，顯示連線問題，不沿用前一次成功狀態。

## 常見誤解

### 使用 ngrok 後，Gateway 就搬到雲端了嗎？

沒有。Gateway 仍在你的電腦上執行；ngrok 提供的是通往它的外部入口。

### 網址有 `https://` 就可以公開管理功能嗎？

不可以。HTTPS 不會自動限制呼叫者身分與功能權限。管理寫入仍需獨立的身分與權限設計。

### 關閉瀏覽器就會停止通道嗎？

不一定。通道是否仍在運作取決於 Agent 或端點狀態，不能只看瀏覽器頁籤。

## 理解確認

- 能分辨本機 API、ngrok Agent 與外部端點。
- 知道外部網址會擴大 API 的接觸範圍。
- 知道 HTTPS、身分驗證與功能權限不是同一件事。
- 知道測試結束後要停止通道，且 authtoken 必須保密。

## 重點整理

- ngrok 可把外部要求轉到本機服務，但 Gateway 仍在本機執行。
- 暫時網址會讓更多用戶端可能接觸 API，因此必須限制資料與功能。
- authtoken 是祕密資料；HTTPS 也不能取代 API 權限。
- 帳號、版本、通道開關與錯誤情境都確認清楚後，才適合進行受控操作。
