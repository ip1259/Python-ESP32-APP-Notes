# BLE：手機與 ESP32 的近距離設定概念

Bluetooth Low Energy（BLE，藍牙低功耗）適合讓附近裝置交換少量資料；在本專題中，它預計只用於手機替 ESP32 設定網路與服務連線資料。

## 你會學到什麼

- 理解 BLE 中央裝置、周邊裝置、掃描與連線的角色。
- 用「服務」與「特徵值」理解 BLE 資料如何分類。
- 分辨讀取、寫入、通知與斷線事件。
- 知道 BLE 設定不參與讀卡、授權或 MQTT 家庭事件分送。

## 開始前

- 本頁是概念教材，不提供手機權限、App、ESP32 韌體、掃描或連線步驟。
- BLE 行為會受手機平台、App 版本、韌體與權限影響。本頁不包含掃描、連線或設定操作。
- Wi-Fi 密碼、服務憑證、UID 與加密金鑰都屬敏感資料，不應出現在畫面、序列輸出、API、MQTT 或截圖中。

## 中央裝置與周邊裝置

在預計的設定流程中：

| 角色 | 本專題中的裝置 | 做什麼 |
| --- | --- | --- |
| 中央裝置（central） | 手機 App | 掃描附近裝置、選擇 ESP32、建立連線並讀寫允許的設定欄位。 |
| 周邊裝置（peripheral） | ESP32 | 宣告自己可被找到，提供預先定義的 BLE 服務與特徵值。 |

「中央」和「周邊」描述本次 BLE 連線中的分工，不表示哪一台裝置比較重要。

## 從掃描到交換資料

```text
ESP32 發出可被發現的訊號
    ↓
手機掃描並辨認目標裝置
    ↓
手機與 ESP32 建立連線
    ↓
手機尋找服務與特徵值
    ↓
依允許方式讀取或寫入
    ↓
確認結果並斷線
```

掃描到名稱不代表裝置身分已安全確認；連線成功也不代表任何特徵值都可以任意讀寫。實作時仍需限制裝置、時間、可用欄位與失敗處理。

## 服務與特徵值

Generic Attribute Profile（GATT，通用屬性設定檔）用服務和特徵值整理 BLE 資料：

- 服務（service）像一個功能資料夾，例如「連線設定」。
- 特徵值（characteristic）像資料夾中的單一欄位，例如「設定狀態」或「API 基底網址」。
- 每個特徵值會規定可讀、可寫或可通知，不是所有資料都支援全部動作。

Bluetooth SIG 的 BLE 入門資料將服務說明為一組相關功能，特徵值則是服務中的單一狀態資料，並具有可用的讀寫性質。

## 讀取、寫入與通知

| 動作 | 資料方向 | 白話用途 |
| --- | --- | --- |
| 讀取（read） | ESP32 → App | App 主動取得目前可讀的值。 |
| 寫入（write） | App → ESP32 | App 將允許的設定送給 ESP32。 |
| 通知（notify） | ESP32 → App | 值改變時，ESP32 主動通知已訂閱的 App。 |
| 斷線（disconnect） | 結束連線 | 完成設定或發生問題時離開本次連線。 |

Thunkable 官方 BLE 文件列出掃描、連線、斷線、字串或位元組收發及斷線監聽等能力。不過平台測試條件並不完全相同，例如官方文件指出 iOS 的 BLE 功能不能直接用 Thunkable Live 測試，因此不能只看積木存在就假設實際手機一定可用。

## 在本專題的位置

```text
手機 App ── BLE 近距離設定 ──> ESP32

ESP32 ── HTTPS API ──> Gateway
Gateway ── MQTT 家庭事件 ──> 訂閱者
```

BLE 只負責附近的設定流程。設定完成後，日常讀卡仍走 Gateway API，家庭情境事件仍由 Gateway 經 MQTT 發布。

BLE 不傳送 UID、授權結果或加密金鑰，也不替代 API 與 MQTT。若設定寫入、重啟讀取、清除設定或失敗復原尚未確認，就維持受控的手動設定方式。

## 安全界線與停止條件

- 找不到明確目標裝置、出現多個無法分辨的同名裝置或手機要求不明權限時，停止連線。
- 設定值若出現在 App 畫面、序列輸出、紀錄或其他可公開位置，停止測試並清除受影響資料。
- 寫入後無法確認 ESP32 是否正確保存、重啟後是否讀回，或無法清除錯誤設定時，不把 BLE 當成正式設定方式。
- BLE 斷線或寫入失敗時，不沿用「設定成功」畫面。

## 常見誤解

### BLE 就是一般藍牙耳機使用的方式嗎？

不完全相同。Bluetooth Classic 常見於持續音訊；BLE 常用於感測器、設定與短量資料交換。本頁聚焦 BLE 的 GATT 資料模型。

### 靠得近就代表連線安全嗎？

不是。距離較近只能縮小使用情境，仍需處理裝置辨認、權限、敏感資料與失敗復原。

### BLE 可以取代 Gateway API 嗎？

不可以。本專題只用 BLE 設定 ESP32 的連線資料；讀卡結果仍由 Gateway API 判斷與回覆。

## 理解確認

- 能分辨中央裝置與周邊裝置。
- 能理解服務包含特徵值，以及特徵值有不同讀寫性質。
- 能分辨讀取、寫入、通知與斷線。
- 知道 BLE 在本專題只負責近距離設定。

## 重點整理

- BLE 適合附近裝置交換少量資料，本專題用它處理 ESP32 連線設定。
- GATT 以服務與特徵值整理資料，並限制可讀、可寫或可通知的動作。
- BLE 不參與讀卡、授權判斷或 MQTT 家庭事件。
- 實際使用前，仍須以手邊的 App、手機、權限與 ESP32 韌體確認相容性。
