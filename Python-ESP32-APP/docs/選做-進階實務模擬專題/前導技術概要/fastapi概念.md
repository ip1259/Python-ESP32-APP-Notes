# FastAPI：Gateway API 的基本概念

FastAPI 是用 Python 建立 API 的工具；API 可以先想成程式之間按照固定格式交換要求與結果的窗口。

## 你會學到什麼

- 理解 API、路徑、請求與回應的意思。
- 分辨 `GET` 與 `POST` 的常見用途。
- 看懂 Python 資料如何成為 JSON 回應。
- 分辨本機 API 與可從外部連入的 API。

## 開始前

- 本頁是概念教材，不需要安裝 FastAPI、執行伺服器或建立公開網址。
- 建議先知道 JSON 是以欄位和值交換資料的文字格式；可參考[`json` 與 `csv`](../../附錄-json與csv.md)。
- 本頁只使用固定假資料，不包含 UID、帳密、token 或私人網址。

## API 像固定的服務窗口

使用 API 時，提出要求的程式稱為用戶端（client），接收要求並回覆的程式稱為伺服器端（server）。HTTP 是兩端傳送要求與回傳結果時常用的一組通訊規則。在本專題中，ESP32 或 App 是用戶端，Gateway 是伺服器端。

```text
ESP32 或 App ── HTTP 請求 ──> Gateway API
ESP32 或 App <── JSON 回應 ── Gateway API
```

雙方要先約好網址路徑、使用方法、欄位與可能的錯誤，否則即使網路連得上，也可能無法正確理解資料。

## 路徑表示要找哪個窗口

網址中的 `/status`、`/events` 等尾端部分稱為路徑（path）。不同路徑可以負責不同事情：

| 路徑情境 | 白話用途 | 專題中的限制 |
| --- | --- | --- |
| `/status` | 讀取目前可公開的最小摘要。 | 不回傳 UID、完整紀錄或管理憑證。 |
| `/events` | 接收一筆固定格式的假事件。 | 必須檢查必要欄位、型別與重複事件代號。 |

這些名稱只是用來理解，不代表後續章節的正式路徑；實際名稱請以第 0 章資料契約與 Gateway 章節為準。

## `GET` 與 `POST` 的差別

| 方法 | 常見用途 | 例子 |
| --- | --- | --- |
| `GET` | 讀取一份既有資料。 | App 取得最近狀態的最小摘要。 |
| `POST` | 送出一份資料，請伺服器處理。 | ESP32 送出固定假事件並等待本次結果。 |

方法只是請求的種類，不會自動提供權限控制。公開網路上的 API 仍需另外處理身分、權限、資料檢查與紀錄範圍。

## 請求與回應

以下是用途示意，不是目前可直接送出的正式資料契約。

```text
請求：POST /events
內容：event_id、device_id、固定假資料與時間

回應：event_id、status、updated_at
```

`event_id` 讓 ESP32 知道回應屬於哪一次要求。若回應的事件代號不同、必要欄位缺少或等待超過時間，就不能沿用前一次的成功結果。

## FastAPI 做了什麼

FastAPI 讓 Python 函式和 API 路徑連在一起。當符合方法與路徑的請求到達時，FastAPI 呼叫對應函式，再把回傳資料轉成 HTTP 回應；Python 字典常會轉成 JSON。

官方文件把「路徑＋方法」稱為路徑操作（path operation）。例如 `GET` 搭配 `/status`，和 `POST` 搭配 `/events`，是兩個不同的操作。

FastAPI 能協助處理資料格式與產生 API 文件，但不會替專題自動決定名單規則、資料保存範圍或誰可以使用管理功能。這些仍是 Gateway 程式的責任。

## 本機與外部連線的差別

`127.0.0.1` 表示「目前這台電腦自己」。只綁定這個位址時，同一台電腦可以使用 API，其他手機或裝置不能直接連入。

當 API 經過 ngrok 等服務提供外部網址後，接觸範圍會改變。暫時 HTTPS 網址不等於 API 已具備完整權限保護；若無法確認外部連線範圍、停止方式與錯誤處理，就只在本機使用。

## 在本專題的位置

```text
ESP32 ── HTTPS API ──> FastAPI Gateway
                           ├─ 檢查資料
                           ├─ 套用規則
                           ├─ 保存最小紀錄
ESP32 <── JSON 回應 ───────┘
```

MQTT 不負責這段讀卡請求與回應。只有 Gateway 已完成判斷後，才可能在後續章節發布不含卡片資料的家庭情境事件。

## 常見誤解

### 有 HTTPS 就代表 API 只有我能用嗎？

不是。HTTPS 保護傳輸過程，但不會自動限制誰可以呼叫每個功能。API 仍需要明確的身分、權限與資料檢查。

### FastAPI 會自動保存資料嗎？

不會。FastAPI 負責接收請求與建立回應；是否保存、保存哪些欄位，以及失敗時怎麼處理，都要由 Gateway 程式決定。

### `POST` 一定代表修改資料嗎？

不一定。它常用來送出資料請伺服器處理，但實際效果仍由該路徑的契約決定。

## 理解確認

- 能分辨用戶端、Gateway API、請求與回應。
- 能理解 `GET` 常用於讀取，`POST` 常用於送出資料。
- 知道路徑與方法共同決定要使用哪個 API 功能。
- 知道本機 API 變成外部可連線時，需要額外安全限制。

## 重點整理

- FastAPI 讓 Python 函式成為可由 HTTP 呼叫的 API 路徑。
- API 雙方必須先約好方法、路徑、欄位、結果與錯誤。
- Gateway 負責資料檢查、規則與最小紀錄；FastAPI 不會自動完成這些決策。
- 本機 API 與外部可連線 API 的風險範圍不同。
