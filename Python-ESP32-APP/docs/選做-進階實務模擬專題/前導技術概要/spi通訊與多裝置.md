# SPI 通訊與多裝置

SPI 是讓 ESP32 與感測器或模組依照共同節拍交換資料的通訊方式；RC522 便會使用它。

## 你會學到什麼

- 理解 `SCK`、`MOSI`、`MISO` 與 `CS`（或 `SS`）各自的用途。
- 看懂 ESP32 與單一 SPI 裝置完成一次資料交換的順序。
- 知道多個 SPI 裝置可以共用部分線路，但每個裝置需要自己的 `CS` 線。
- 知道電壓、SPI 模式與通訊速度不相容時，不能直接把裝置接到同一組線路。

## 開始前

- 本頁是概念教材，不需要接線、供電或執行程式。
- 實際使用前，應先確認 ESP32 與每個模組的規格；不同模組的腳位名稱、可用電壓、SPI 模式與最高速度可能不同。
- ESP32 的 GPIO 使用 `3.3V` 邏輯訊號。規格不相容或不確定時，先停止接線，不要把 `5V` 訊號直接接到 ESP32 GPIO。

## SPI 在做什麼

SPI 是一種由控制端主動開始的序列通訊方式。這裡可以先把 ESP32 想成控制端：它選擇要交談的模組、送出節拍，並在節拍中交換資料。被選到的模組才會回應。

Espressif 將一次 SPI 交易定義為：控制端啟用一條 `CS` 線，和一個裝置傳送或接收資料，再把 `CS` 回到未啟用狀態。一次交易進行時，不會被另一筆交易插入。

## 四條常見線路

| 線路 | 全名與資料方向 | 白話用途 |
| --- | --- | --- |
| `SCK` 或 `SCLK` | Serial Clock；ESP32 → 裝置 | 時脈線。ESP32 送出規律的節拍，讓雙方知道何時送出或讀取每一個資料位元。 |
| `MOSI` | Master Out, Slave In；ESP32 → 裝置 | 資料從 ESP32 前往被選到的裝置，例如要求它讀取某個資料。 |
| `MISO` | Master In, Slave Out；裝置 → ESP32 | 資料從被選到的裝置回到 ESP32，例如讀取結果或狀態。 |
| `CS` 或 `SS` | Chip Select 或 Slave Select；ESP32 → 裝置 | 選擇線。ESP32 用它指定這一刻要和哪一個裝置交談。 |

`CS` 與 `SS` 在一般 SPI 教材中常指相同用途，只是名稱不同。模組資料表可能把它寫成 `CS`、`SS`、`NSS` 或其他相近名稱，實際連接前仍要以該模組的資料表為準。

## 一個裝置時，資料怎麼交換

下列流程圖只用來說明資料流，不是接線圖或操作步驟。

```text
ESP32 啟用 RC522 的 CS
  → ESP32 在 SCK 節拍下，從 MOSI 送出要求
  → RC522 在相同節拍下，從 MISO 回傳資料
  → ESP32 停止這次資料交換
  → ESP32 解除 RC522 的 CS
```

同一個節拍中，`MOSI` 與 `MISO` 可以各自傳送資料；不過實際一筆交易要傳什麼、何時回應，仍由裝置的通訊規格決定。不要把所有 SPI 裝置都想成能使用同一組資料格式。

## 多個裝置如何共用 SPI

一個 ESP32 的 SPI 匯流排可以連接多個裝置。這些裝置共用 `SCK`、`MOSI` 與 `MISO`，但每個裝置各有一條自己的 `CS` 線。ESP32 一次只啟用其中一條 `CS`，因此只有被選到的裝置會參與本次交易。

```text
ESP32 GPIO A ───── 裝置 A 的 CS
ESP32 GPIO B ───── 裝置 B 的 CS
ESP32 GPIO C ───── 裝置 C 的 CS

ESP32 的 SCK  ───── 裝置 A、B、C 共用
ESP32 的 MOSI ───── 裝置 A、B、C 共用
ESP32 的 MISO ───── 裝置 A、B、C 共用
```

上圖中的每條 `CS` 都是不同的 ESP32 GPIO。ESP32 不能同時選取兩個一般 SPI 裝置；若同時選取，兩個裝置可能一起解讀資料，回傳資料也可能互相衝突。

### 為什麼未選取的裝置要釋放 `MISO`

多個裝置共用同一條 `MISO`。當裝置沒有被自己的 `CS` 選取時，它不應主動把高電位或低電位送到 `MISO`，而是讓這條輸出維持不驅動的狀態。這常稱為高阻抗（high impedance）：可以把它想成暫時不開口說話，讓被選到的裝置能單獨回覆 ESP32。

如果未選取的裝置仍持續驅動 `MISO`，就可能和另一個裝置同時在同一條線上送出不同訊號，造成資料讀取錯誤。選擇 SPI 模組時，需確認它在未被選取時能正確處理 `MISO`；不確定時不要直接加入現有的 SPI 匯流排。

## 共用線路前，還要確認什麼

多裝置共用線路不代表它們的所有設定都相同。實際規劃時，至少要確認下列限制。

| 要確認的項目 | 為什麼重要 | 不確定時怎麼做 |
| --- | --- | --- |
| 邏輯電壓 | `3.3V` 與 `5V` 的訊號不能假設能直接相接；不相容可能讀錯資料或損壞 GPIO。 | 查 ESP32 與模組規格；未確認前不要接線。 |
| SPI 模式 | 裝置會規定時脈閒置時的電位，以及在哪個時刻讀取資料。這兩項合起來稱為 SPI 模式。 | 依各裝置資料表設定；若模式不清楚，先停止，不猜測。 |
| 通訊速度 | 時脈太快時，模組或導線長度可能無法穩定交換資料。 | 以每個裝置規格為準，從共同可接受的較低速度開始確認。 |
| `CS` 狀態 | 每個裝置必須有獨立的 `CS`，而且未被選取時要保持未啟用。 | 在接線與程式都確認後，再加入下一個裝置。 |

同一組 `SCK`、`MOSI`、`MISO` 可以服務不同的裝置；ESP32 在選取不同 `CS` 時，也能依該裝置的規格使用不同的模式或速度。不過這需要正確的程式設定，不能只靠把線路接在一起。

## RC522 的 `SDA` 為什麼不是 I2C 資料線

許多 RC522 模組把 SPI 的選擇腳位標成 `SDA`。在這個模組的 SPI 使用方式中，這個 `SDA` 實際上是用來選取 RC522 的 `SS` 或 `CS`，不是 I2C 常見的 `SDA` 資料線。

因此，看到 RC522 模組上的 `SDA` 時，不能只依名稱判斷用途；要先確認該模組目前使用的通訊模式與資料表。後續 RC522 教材會以 SPI 與 `SS`／`CS` 的角色來說明它。

## 常見誤解

### `MOSI` 和 `MISO` 的方向會隨裝置改變嗎？

不會。名稱是從 ESP32 作為控制端的角度來看：`MOSI` 是 ESP32 送出資料，`MISO` 是 ESP32 收回資料。把線路接反時，裝置可能完全沒有回應。

### 多個裝置共用 SPI，就是把每一條線都接在一起嗎？

不是。`SCK`、`MOSI`、`MISO` 可以共用，但每個一般 SPI 裝置需要獨立的 `CS`。此外，還要確認每個裝置的電壓、模式、速度與未選取時的 `MISO` 行為。

### RC522 的 `SDA` 可以接到 ESP32 的 I2C `SDA` 腳嗎？

不能只因為名稱相同就這樣連接。RC522 模組常把 SPI 的 `SS`／`CS` 標成 `SDA`；它的角色是選取 RC522，不是 I2C 資料線。

## 理解確認

- 能辨認 `SCK`、`MOSI`、`MISO` 與 `CS` 的資料方向和用途。
- 能理解一次 SPI 交易只選取一個裝置，並在交易結束後解除選取。
- 能分辨多裝置時可共用的三條線，以及每個裝置必須獨有的 `CS` 線。
- 知道多裝置共用 `MISO` 時，未選取裝置需不驅動這條線；實際行為要以模組規格確認。

## 重點整理

- `SCK` 提供節拍，`MOSI` 讓 ESP32 送資料，`MISO` 讓裝置回傳資料，`CS`／`SS` 用來選取裝置。
- 多個 SPI 裝置可共用 `SCK`、`MOSI`、`MISO`，每個裝置要有自己的 `CS`。
- 多裝置共用 `MISO` 時，未選取裝置需不驅動這條線；實際行為要以模組規格確認。
- 實際共用前要確認邏輯電壓、SPI 模式、速度和各模組規格。
- RC522 標示為 `SDA` 的腳位，在 SPI 使用情境通常是它的 `SS`／`CS`。
